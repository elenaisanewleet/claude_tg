# claude-tg — Claude Code внутри Telegram

Полноценный клиент Claude прямо в мессенджере: пишешь в чат — отвечает тот же
Claude Code, что и в терминале. Со своими сессиями, выбором модели, уровнем
рассуждений (effort), режимами доступа к инструментам, файлами и подтверждениями
опасных действий.

Бот **приватный**: доступ есть только у владельца, остальные попадают внутрь
исключительно по его кнопке «Открыть доступ».

```
Telegram  ──►  claude-tg (этот бот)  ──►  CLI `claude` (Claude Code)  ──►  Anthropic
   ▲                   │                         │
   └── стрим ответа ◄──┘                    рабочая папка сессии
```

Бот не содержит собственной «модели» и не ходит в API напрямую. Он запускает
настоящий Claude Code через официальный `claude-agent-sdk` — поэтому получает
ровно те же возможности, что и десктопный клиент: инструменты, скиллы,
подключённые MCP-серверы, `CLAUDE.md`, автосжатие контекста.

---

## Что умеет

| Возможность | Как это выглядит в Telegram |
|---|---|
| Диалог с Claude | Просто пишешь сообщение, ответ печатается «вживую» |
| Выбор модели | `/model` — Opus / Sonnet / Fable / Haiku, алиасом или конкретной версией |
| Уровень рассуждений | `/effort` — `low` · `medium` · `high` · `xhigh` · `max` |
| Режимы доступа | `/mode` — спрашивать, править файлы без спроса, план, авто, без ограничений |
| Extended thinking | `/thinking` — адаптивное, с показом выжимки, выключено |
| Сессии | `/new`, `/sessions`, `/resume`, `/fork` — контекст переживает перезапуск бота |
| Файлы туда | Кидаешь документ/фото в чат — файл ложится в рабочую папку сессии |
| Файлы обратно | Всё, что Claude кладёт в `outbox/`, автоматически приходит в чат |
| Подтверждения | Опасное действие → кнопки «Разрешить / Запретить / Всегда» |
| Прерывание | `/stop` останавливает текущий ход, не убивая сессию |
| Расход | `/status` — модель, режим, заполненность контекста, стоимость |
| Актуальность | `/version` и `/update`; плюс ночное автообновление Claude Code и SDK |

## Установка

### Что нужно заранее

* **Node.js 18+** и **Claude Code**: `npm install -g @anthropic-ai/claude-code`
* **Python 3.11+**
* **Подписка Claude** (Pro / Max) либо `ANTHROPIC_API_KEY`
* **Токен бота** от [@BotFather](https://t.me/BotFather)

### Быстрый старт

```bash
git clone https://github.com/smmsemmers/claude_tg.git
cd claude_tg

./deploy/install.sh          # venv, зависимости, проверка Claude Code

claude auth login            # один раз: вход под своей подпиской

cp .env.example .env         # если install.sh ещё не сделал
$EDITOR .env                 # TELEGRAM_BOT_TOKEN и OWNER_USER_ID

./.venv/bin/python -m claude_tg
```

`OWNER_USER_ID` — твой числовой Telegram id. Самый простой способ узнать:
запусти бота без него не получится, поэтому спроси у [@userinfobot](https://t.me/userinfobot)
или временно поставь любое число, напиши боту `/id` (эта команда работает
без доступа) и подставь настоящий.

### Меню команд в Telegram

Отправь [@BotFather](https://t.me/BotFather) команду `/setcommands`, выбери бота
и вставь содержимое `botfather-commands.txt`.

### Docker

```bash
cp .env.example .env && $EDITOR .env
docker compose build
docker compose run --rm claude-tg claude auth login   # вход, сохранится в томе
docker compose up -d
```

### Автозапуск

* **Linux (systemd)**: `deploy/claude-tg.service` — поправь пути, затем
  `sudo systemctl enable --now claude-tg`.
* **macOS (launchd)**: `deploy/com.claude-tg.bot.plist` — замени `USERNAME`,
  положи в `~/Library/LaunchAgents/`, потом `launchctl load -w …`.

### На сервере

Отдельная инструкция — **[docs/deploy.md](docs/deploy.md)**: авторизация без
браузера через `claude setup-token`, пошаговая установка на Ubuntu, Docker,
диагностика. Там же — почему **Vercel и подобные serverless-платформы не
подойдут** (боту нужен долгоживущий процесс, дочерний CLI и постоянный диск) и
почему **сервер внутри России не заработает** (Anthropic не обслуживает
регион).

## Доступ: бот только твой

1. Незнакомый человек пишет боту → он получает вежливый отказ, а **тебе**
   приходит карточка с кнопками **«Открыть доступ» / «Отказать»**.
2. Можно и вручную: `/grant <user_id>`, `/revoke <user_id>`, `/block <user_id>`.
3. `/users` — кто уже внутри и кто ждёт решения.
4. Тех, кому доверяешь заранее, впиши в `ALLOWED_USER_IDS` в `.env` — они зайдут
   без запроса.

Владелец (`OWNER_USER_ID`) всегда имеет доступ и всегда может его раздавать.
Никто другой команды управления доступом использовать не может.

## Как всё устроено

### Сессии

Одна сессия Claude = один чат (в группах — один тред). Её id хранится в SQLite,
поэтому перезапуск бота, смена модели или обновление Claude Code **не теряют
контекст**: процесс поднимается заново с `--resume`.

* `/new` — начать с чистого листа (старая сессия остаётся в истории)
* `/sessions` — список сохранённых сессий с кнопками возврата
* `/fork` — сделать копию текущей: экспериментируешь, не портя основную ветку
* `/ws` — где лежит рабочая папка и что в ней

### Файлы

У каждой сессии своя папка (по умолчанию `~/.claude-tg/workspaces/<user>/<chat>`):

```
inbox/    ← сюда попадает всё, что ты присылаешь в чат
outbox/   → всё, что Claude сюда положит, бот пришлёт файлом в чат
```

Claude работает внутри этой папки как в обычном проекте: читает, пишет, запускает
команды. Telegram отдаёт ботам файлы не больше 20 МБ — это ограничение Telegram,
не бота.

### Разрешения

В режиме `default` каждый потенциально опасный вызов инструмента приходит
отдельным сообщением с кнопками:

* **Разрешить** — только этот раз
* **Всегда в этой сессии** — до перезапуска процесса
* **Запретить** — Claude получит отказ и придумает другой путь

Если не ответить за `PERMISSION_TIMEOUT` (по умолчанию 5 минут), действие
отменяется. Хочешь меньше вопросов — `/mode acceptEdits` или `/mode dontAsk`.
`/mode bypassPermissions` снимает проверки полностью — только для песочницы.

### Модели и effort

Алиасы `opus`, `sonnet`, `fable`, `haiku` всегда указывают на **свежую** версию
линейки — меню не устаревает, когда выходит новая модель. Конкретные версии
(`claude-opus-5`, `claude-sonnet-5`, …) доступны отдельной группой, если нужно
закрепиться. `/model <любое имя>` примет и то, чего ещё нет в списке.

Effort управляет глубиной рассуждений и расходом токенов: `xhigh` — лучший выбор
для кода и агентных задач, `high` — разумное умолчание, `low`/`medium` — когда
важнее скорость.

Модель и режим доступа меняются **на лету**. Effort и thinking требуют
перезапуска процесса — бот делает это сам, контекст сессии сохраняется.

## Поддержание актуальности

Claude развивается быстро, и бот намеренно не дублирует его логику — он остаётся
тонкой оболочкой. Актуальность обеспечивается тремя способами:

1. **Ночное автообновление** (`AUTO_UPDATE=true`): раз в сутки выполняется
   `claude update` и `pip install -U claude-agent-sdk`. Если версия изменилась,
   владелец получает отчёт. Под systemd/launchd с `Restart=always` бот
   подхватит новую версию сам.
2. **`/update`** — то же самое по требованию (только владелец).
3. **`/version`** — что стоит сейчас и что лежит в npm.

Плюс алиасы моделей: `opus` завтра будет указывать на следующий Opus без единой
правки в коде.

## Настройки `.env`

Все параметры и их значения по умолчанию описаны в `.env.example`. Самое важное:

| Переменная | Смысл |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен от @BotFather |
| `OWNER_USER_ID` | Твой Telegram id — единственный админ |
| `ALLOWED_USER_IDS` | Кого пускать без запроса |
| `CLAUDE_CLI_PATH` | Путь к `claude`, если его нет в `PATH` |
| `DEFAULT_MODEL` / `DEFAULT_EFFORT` | Стартовые значения для новых чатов |
| `DEFAULT_PERMISSION_MODE` | `default` — спрашивать (рекомендуется) |
| `SHOW_THINKING` / `SHOW_TOOLS` / `SHOW_FOOTER` | Что показывать в ответах |
| `STREAM_INTERVAL` | Как часто править сообщение при стриминге, сек |
| `AUTO_UPDATE` / `AUTO_UPDATE_HOUR` | Ночное обновление Claude Code и SDK |

## Группы

В личке бот отвечает на всё. В группе — только когда его упомянули (`@bot …`)
или ответили реплаем на его сообщение, чтобы не мешать обсуждению. В форумах
каждый тред получает свою сессию.

---

## Чего бот не делает

* **Не расшифровывает голосовые.** Файл сохраняется в `inbox/`, но текст из него
  бот сам не достаёт — у Claude Code нет распознавания речи.
* **Не отдаёт файлы больше ~45 МБ** — ограничение Telegram на отправку ботом.
* **Не заменяет терминал в мелочах**: интерактивные TUI-подсказки Claude Code
  (выбор из списка стрелками) в Telegram недоступны — вместо них кнопки.
* **Один ход за раз на сессию.** Пока идёт ответ, новое сообщение получит
  подсказку подождать или `/stop`.

## Разработка

```bash
./.venv/bin/python -m pytest -q      # 60 тестов
./.venv/bin/ruff check .             # линтер
```

Структура:

```
claude_tg/
  config.py       — настройки из .env
  catalog.py      — модели, effort, режимы, thinking
  storage.py      — SQLite: доступы, настройки, привязка чатов к сессиям
  access.py       — белый список и заявки на доступ
  bridge.py       — обёртка над claude-agent-sdk: сессия, поток событий
  streamer.py     — живой рендер ответа в сообщения Telegram
  telegram_md.py  — markdown → HTML + безопасная нарезка
  ui.py           — клавиатуры и разметка callback_data
  app.py          — общий контекст, запросы разрешений
  bot.py          — сборка приложения и расписания
  updater.py      — обновление Claude Code и SDK
  handlers/       — команды и сообщения
```
